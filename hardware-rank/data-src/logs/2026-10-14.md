## 一、结转第 1 条作废：浏览器工具在本机不可用

10-13 把固态专项的唯一出路定为「用浏览器工具（非 `web_fetch`）打开 `wxdh.com`」。今天执行，直接撞墙：

```
browser(navigate https://www.wxdh.com/)
→ Failed to start Chrome CDP on port 18800 for profile "openclaw"
→ Chrome stderr: Running as root without --no-sandbox is not supported.
→ 工具自带提示：Do NOT retry the browser tool — it will keep failing.
```

`web_fetch` 同一域名当场复现 10-13 的 `request timed out`。**两条路同时死。**

**结论要写准确：这不是「方法错了」，10-13 对 `wxdh.com` 形态的判断（全池、同时点、价格/券后价分列）仍然成立；是本机 Chrome 跑在 root 下缺 `--no-sandbox`，渲染型抓取这条能力在当前环境里根本不存在。** 这意味着：

- **固态整池专项在环境变更前无法推进。** 10-09 的逐 SKU 路线已被 10-13 证伪（命中率实测 1/4），今天渲染型抓取又被证明不可用——**两条路都走完了，专项应当从「每日结转」里摘出来，降级为「等环境」**，不要再占每轮的优先级 1 位。
- 需要的环境变更是明确的一项：`browser.noSandbox: true`（工具错误信息自己给了这个提示）。**这是配置决定，不是每日更新能做的**，和 `psus.json` 的 `tier`/`oem` schema 阻塞同性质，归入「需单独起会话」那一类。

## 新增方法论（本轮四条）

- **「层级对」只是入场券。** 确认一个数字属于库内口径层之后，还要过两关：**无当期反向信号**（9070 GRE 被这关拦下）、**无同层打架**（5070 / 5060Ti 被这关拦下）。今天一张表里 8 个数字，只有 2 个三关全过
- **改一个无源数字去等观察窗口，不算消费窗口，反而是在给窗口立基线。** 5070 Ti 从 9394（无源）换成 9100（有源有日期），「跌破 9000」这一问原封不动，但判的时候有了可比基线
- **模板回收站的识别判据：跨日比对同一张表。** 行情站若连续三天同一行纹丝不动、而另一行单日跳 1500，是表格挪行不是行情。再叠加**档位倒挂**（5080 报价低于 5070 Ti 上沿）即可判定。新增 `hutaodewang.com`
- **SKU 代际差（D / D V2）与容量差同级，都属「不明即弃」。** 5090 D 三个候选值差 1.5 万，不是噪声是不同的卡。**而且要先确认库内条目指哪一代，再去找价**——顺序反了会把正确的报价落到错误的条目上
